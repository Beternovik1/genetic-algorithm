REPARTICIÓN DE TAREAS — PROYECTO 02
Detección de círculos en imágenes usando un algoritmo genético
Equipo de 5 integrantes

=======================================================================
OBJETIVO GENERAL
=======================================================================
Aplicar el algoritmo genético simple (visto en clase) para detectar
círculos en imágenes BMP de prueba. Ejecutar 100 veces por imagen,
calcular promedio y desviación estándar de las propiedades del círculo
detectado. Entregar: código, configuraciones, pruebas, análisis,
reporte PDF (por integrante) y video demostrativo.

=======================================================================
DIVISIÓN DE TRABAJO
=======================================================================

Los integrantes 1, 2 y 3 se encargan de TODO el desarrollo técnico
(código, configuraciones, pruebas, resultados).
Los integrantes 4 y 5 se encargan de TODO lo relacionado con el
análisis, reporte y video.

=======================================================================
INTEGRANTE 1 — IMPLEMENTACIÓN DEL ALGORITMO GENÉTICO
=======================================================================

Responsabilidad: Implementar el núcleo del algoritmo genético para la
detección de círculos en imágenes.

Tareas:
• Adaptar el código del AG simple visto en clase.
• Representar el cromosoma como una tupla de 3 valores reales:
  (centro_x, centro_y, radio).
• Implementar la función de fitness que evalúe qué tan bien un
  círculo candidate coincide con los bordes de la imagen. Sugerencia:
  usar detección de bordes (Canny) y contar cuántos píxeles del
  círculo caen sobre bordes detectados.
• Implementar operadores genéticos:
  - Selección: torneo o ruleta.
  - Cruza: de uno o dos puntos.
  - Mutación: modificar ligeramente x, y, r con probabilidad.
  - Elitismo (opcional).
• El programa debe cargar imágenes BMP en escala de grises.
• Entregar el código fuente bien documentado (comentarios técnicos).
• Lenguaje sugerido: Python con OpenCV (cv2) y NumPy.

Entregables:
- Código fuente del AG funcional.

=======================================================================
INTEGRANTE 2 — SINTONIZACIÓN DE PARÁMETROS + AUTOMATIZACIÓN DE PRUEBAS
=======================================================================

Responsabilidad: Encontrar la configuración óptima del AG y construir
el script que automatice las pruebas estadísticas.

Tareas — Sintonización:
• Probar diferentes configuraciones variando:
  - Tamaño de población: 50, 100, 200, 500
  - Tasa de mutación: 0.01, 0.05, 0.1, 0.2
  - Tasa de cruza: 0.5, 0.7, 0.9
  - Número de generaciones: 100, 200, 500, 1000
  - Tipo de selección: torneo vs ruleta
  - Elitismo: activado / desactivado
• Documentar en una tabla todas las combinaciones probadas y los
  resultados obtenidos (fitness promedio).
• Determinar y justificar cuál es la mejor configuración.

Tareas — Automatización:
• Crear un script (test_runner.py) que:
  - Cargue una imagen.
  - Ejecute el AG N veces (configurable, default 100).
  - Guarde en un archivo CSV los resultados de cada ejecución:
    imagen, centro_x, centro_y, radio, fitness.
  - Calcule promedio y desviación estándar de cada propiedad.
  - Genere una tabla resumen por imagen.

Entregables:
- Tabla de configuraciones probadas con la mejor configuración.
- Script test_runner.py para automatizar pruebas.

INTEGRANTE 4 — ANÁLISIS DE RESULTADOS Y GRÁFICAS + REPORTE
=======================================================================

Responsabilidad: Analizar los resultados obtenidos por el equipo,
generar visualizaciones y redactar la sección de análisis del reporte.

Tareas — Análisis:
• Utilizar los datos generados por el Integrante 3.
• Responder preguntas como:
  - ¿En qué imágenes el AG converge a un círculo cercano al real?
  - ¿En cuáles hay mayor variabilidad (desviación estándar alta)?
  - ¿El AG encuentra siempre el mismo círculo o hay múltiples modas?
  - ¿Cómo afecta el fondo de la imagen al rendimiento?
• Generar gráficas:
  - Gráfica de convergencia (fitness vs generaciones) para una
    ejecución representativa de cada imagen.
  - Diagramas de dispersión de los círculos detectados (x, y, r).
  - Comparativa de promedios entre imágenes (gráfica de barras).

Tareas — Reporte:
• Redactar la sección de "Análisis de Resultados" del reporte final.
• Incluir las gráficas generadas.
• Escribir las conclusiones del proyecto.
• Coordinar con el Integrante 5 la integración del reporte final.

Entregables:
- Gráficas en formato PNG/PDF.
- Sección de análisis y conclusiones redactada.

USO DE GITHUB — REPOSITORIO OFICIAL
=======================================================================

El repositorio oficial del proyecto es:
https://github.com/Beternovik1/genetic-algorithm.git

Todos los integrantes deben realizar una contribución de prueba
mediante Pull Request para familiarizarse con el flujo de trabajo
antes de subir el código real.

Instrucciones:

1. Crear una cuenta en GitHub (si no se tiene) en github.com.

2. Clonar el repositorio:
   git clone https://github.com/Beternovik1/genetic-algorithm.git

3. Crear un archivo individual de prueba dentro de la carpeta
   "integrantes/" con el nombre "integrante{N}.txt" (ej.
   integrante1.txt). El contenido debe ser el nombre del
   integrante y un resumen de una línea de su tarea asignada.

4. Subir el cambio mediante Pull Request (PR):
   a) Crear una rama nueva:
      git checkout -b integrante{N}-prueba
   b) Agregar el archivo:
      git add integrantes/integrante{N}.txt
   c) Hacer commit:
      git commit -m "feat: archivo de prueba integrante {N}"
   d) Subir la rama:
      git push origin integrante{N}-prueba
   e) Desde GitHub.com, abrir un Pull Request de esa rama hacia
      main.

Este ejercicio de prueba asegura que no haya contratiempos cuando
se suba el código real del proyecto.

Flujo de trabajo durante el proyecto:
  • Cada integrante trabaja en su propia rama.
  • Al terminar una funcionalidad, abre un Pull Request a main.
  • Otro integrante revisa y aprueba el PR antes de fusionarlo.
  • Siempre hacer git pull antes de empezar a trabajar para tener
    la versión más reciente.

Alternativa: Si alguien tiene dificultades con git, puede compartir
sus archivos por otro medio y otro integrante los integra, pero
usar GitHub queda más profesional y permite al profesor consultar
el historial de contribuciones.
